**TS Media chat 2.7.4** fixes the white flash of TeamSpeak's window when TeamSpeak starts with dark mode on, and it is an important update: TS Media chat 2.4.0 and later with automatic update checks on install it without a click ([how](https://github.com/Metihttp/Teamspeak_Media_chat/blob/v2.7.4/docs/UPDATES.md#important-updates)) and it starts the next time you open TeamSpeak, while everyone else gets the usual update offer when TS Media checks for updates.

### Highlights

- **No white flash at a start.** When TeamSpeak starts with dark mode on, its window is dark from the first moment it appears, instead of white for a moment.

### Fixed

- Dark mode: TeamSpeak's window no longer flashes white when TeamSpeak starts with dark mode on. Windows showed the window before TeamSpeak had drawn it, so it was white for about a tenth of a second (2.7.3 made that a little longer). Now it is dark from the first moment it appears (it then opens without Windows' fade-in animation, which showed it white).
- Dark mode's [FAQ](https://github.com/Metihttp/Teamspeak_Media_chat/blob/v2.7.4/docs/FAQ.md#some-names-in-the-channel-tree-keep-their-colors-in-dark-mode) and [description](https://github.com/Metihttp/Teamspeak_Media_chat/blob/v2.7.4/docs/USAGE.md#dark-mode) say exactly which colors the news line at the bottom of TeamSpeak's window has: the ones it had when TeamSpeak showed the news. TeamSpeak draws that line once when it shows the news and keeps the drawing, and a plugin can't make it draw it again, so news shown while dark mode was on keeps dark mode's light colors after it goes off, and news shown before you turned it on keeps your style's colors in dark mode. The FAQ said only the first, and that it lasted until TeamSpeak draws the line anew.
- Releases: `scripts\build.ps1 -Important` and `-VerifyPublished` name 2.4.0 as the first version that installs an important update by itself (they said 2.3.4, which was never released), and [updates](https://github.com/Metihttp/Teamspeak_Media_chat/blob/v2.7.4/docs/UPDATES.md#on-disk) says that `state.ini` keeps the version of an important update installed without a click in `[install] automatic` (it said `automatic=1`).

### Install or update

**On 2.4.0 or later (2.4.0, 2.5.0, 2.6.0, 2.7.0, 2.7.1, 2.7.2 or 2.7.3) with automatic update checks on:** nothing to do. This is an important update: TS Media's daily update check downloads 2.7.4, checks every file against the SHA-256 the author signed for it, and installs it without a click. It starts the next time you open TeamSpeak; to start it now, use **Check for updates…** in the plugin menu, then **Restart TeamSpeak now**. If it can't be installed that way (for example while TS Media hasn't shown its one-time line about important updates in the chat yet, which waits for a server connection), you get the usual update offer instead ([details](https://github.com/Metihttp/Teamspeak_Media_chat/blob/v2.7.4/docs/UPDATES.md#important-updates)).

**On 2.2.1 or later otherwise (2.2.1 to 2.3.3, or automatic checks off):** use **Check for updates…** in the plugin menu (with automatic checks on, the update offer also comes by itself), then click **Update**. On 2.2.0 it updates to 2.2.1 first, then to 2.7.4. Your settings, cache and GIFs are kept.

**On 2.1 or older, or new here?** Close TeamSpeak, double-click the file above, then type `/tsmedia` in the chat.

### Known issues

- The 32-bit DLL is untested on a real 32-bit client, and it has no YouTube player (Play opens your browser).
- In dark mode, web pages inside TeamSpeak (the Addons browser, myTeamSpeak), the YouTube player's page and a few names TeamSpeak colors in the channel tree (friends, blocked people, someone recording) keep their own colors: [why](https://github.com/Metihttp/Teamspeak_Media_chat/blob/v2.7.4/docs/FAQ.md#some-names-in-the-channel-tree-keep-their-colors-in-dark-mode).
- With *Use Windows proxy settings*, a Windows setup script that answers with a SOCKS proxy can still send the update check directly, and the YouTube player through SOCKS with names looked up on your PC; the chat proxy avoids this.
- TeamSpeak may crash or hang when it quits, with or without the plugin: [workaround](https://github.com/Metihttp/Teamspeak_Media_chat/blob/main/docs/FAQ.md#teamspeak-crashes-or-hangs-when-i-quit).
